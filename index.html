        TERRAFORM
        
Production AWS Infrastructure with Terraform

        ⌥ view on GitHub →
      

      

        

          A highly available, multi-AZ AWS environment defined entirely as code. Nothing in it was
          clicked together in the console — the whole stack can be destroyed and rebuilt from an
          empty account with a single terraform apply, which is exactly how I tested it.
        

        

          

            
Network

    • 
              
  • Public and private subnets with separate route tables

    • 
              
  • Security Groups scoped so only the ALB can reach the instances

Compute & Traffic

            
    
              
  • EC2 instances in an Auto Scaling Group across both AZs

  • Application Load Balancer with target groups and health checks
    • 
              
  • Launch template with user data for instance bootstrap

  • Unhealthy instances drained and replaced without downtime

State & Security

# backend.tf — remote state, locked so two applies can't collide
terraform {
  backend "s3" {
    bucket         = "sdc-tfstate-prod"
    key            = "network/terraform.tfstate"
    region         = "us-east-1"
    dynamodb_table = "tf-state-lock"
    encrypt        = true
  }
}

# The ALB is the only thing allowed to talk to the instances.
resource "aws_security_group_rule" "alb_to_app" {
  type                     = "ingress"
  from_port                = 80
  to_port                  = 80
  protocol                 = "tcp"
  security_group_id        = aws_security_group.app.id
  source_security_group_id = aws_security_group.alb.id
}

        

      

    


    
    

      

        KUBERNETES
        
Containerized Workloads on Amazon EKS

        ⌥ view on GitHub →
      

      

        

          An EKS cluster running a containerized application with rolling updates, autoscaling, and
          no hardcoded AWS credentials anywhere in the cluster. The piece I'm proudest of is IRSA —

# The annotation is the whole trick: the pod exchanges its projected
# service-account token for temporary AWS credentials via STS.
apiVersion: v1
kind: ServiceAccount
metadata:
  name: app-s3-reader
  namespace: production
  annotations:
    eks.amazonaws.com/role-arn: arn:aws:iam::<acct>:role/app-s3-reader
---
spec:
  serviceAccountName: app-s3-reader   # no AWS keys in the image, ever
  containers:
    - name: web
      readinessProbe:
        httpGet: { path: /healthz, port: 8080 }

        

      

    


    
    

      

        CI/CD
        
GitHub Actions Pipeline for Infrastructure as Code

        ⌥ view on GitHub →
      

      

        

          The safety net around the Terraform above. Every pull request gets formatted, validated,
          and planned automatically, and the plan output is posted to the PR so a human reviews the
          diff before anything touches real infrastructure. Applies only run after an explicit approval.
        

        

          

            
Pipeline

            
    
              
  • terraform fmt -check and validate on every push
    • 
              
  • terraform plan on pull requests, output commented on the PR
    • 
              
  • terraform apply gated behind a protected environment
    • 
              
  • Manual approval required before production applies
    • 
            

          

          

            
Safety

            
    
              
  • Drift detection catches manual console changes
    • 
              
  • State locking prevents two pipelines applying at once
    • 
              
  • Rollback path via previous known-good state version
    • 
              
  • Short-lived credentials through OIDC — no static secrets in the repo
    • 
            

          

        

        

          GitHub ActionsTerraformOIDCJenkins
          BashApproval Gates
        

        
        


name: terraform
on: { pull_request: { branches: [main] } }

permissions:
  id-token: write   # OIDC — no long-lived AWS keys in GitHub secrets
  contents: read
  pull-requests: write

jobs:
  plan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::<acct>:role/gha-terraform
          aws-region: us-east-1
      - run: terraform fmt -check -recursive
      - run: terraform init && terraform validate
      - run: terraform plan -no-color -out=tfplan
